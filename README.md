# 股票記帳

多人多帳戶的股票交易記帳與統計 App。用 Flutter 寫，同一份程式碼可以編譯成
**Windows 版**和 **Android 版**。資料只存在裝置本機，不會上傳到任何雲端伺服器。

程式碼在 [`app/`](app) 資料夾。

## 功能（第一階段）

- **群體**：可以建立多個完全獨立的「群體」（各自的戶名、帳戶、交易、關注
  清單、備份，互不相通），例如「我自己」和「幫朋友代操」分開記，設定頁或
  總覽頁右上角隨時切換。
- **多人多帳戶**：一個群體裡可以新增多個戶名，每個戶名底下可以有多個券商
  帳戶，各自設定手續費折扣。
- **交易紀錄**：新增、修改、刪除買賣交易。手續費（0.1425% × 帳戶折扣，最低
  20 元）和交易稅（賣出 0.3%）會自動算好，也可以手動改成對帳單上的實際金額。
- **統計**：個股 → 個人（可再細分到每個券商帳戶）→ 全部人合計，三層都有
  持股、成本、市值、未實現／已實現損益。
- **即時股價**：按「更新股價」抓證交所的即時報價，可以隨時手動更新。
- **查詢股票**：輸入代號或名稱查詢任何台股，不限自己持有的。
- **資訊 / 新聞**：抓 Google 新聞，列出持有中和關注股票的近期新聞，同一則
  被多家媒體轉載時會合併成一則。可以把還沒買的股票加入「關注清單」。
- **選股雷達**（資訊頁子分頁）：抓候選股（熱門股/ETF 候選池，或全市場
  2300 多檔）當天的即時報價，用「今日漲幅、量能、股價貼近今日高點」
  這些公開、可計算的訊號排名，附上每一檔的理由。**這是機械化的排序，
  不是投資建議、也不是預測**，畫面上一定會顯示這個提醒——沒有任何規則
  能保證排出來的股票之後會賺錢，純粹是幫忙從一堆股票裡篩出「今天表現
  比較突出」的候選，最終判斷還是要使用者自己來。
- **備份**：匯出、匯入 JSON 備份檔，換裝置或重灌時用來還原資料。設定頁
  另外有「匯出/匯入全部群體備份」，一次把所有群體（不只目前這個）都
  打包匯出，換新裝置（例如手機全新安裝）時一次全部匯入，備份裡的群體
  本機沒有就自動建立，名稱都會照樣建好。
- **畫面自動適應**：視窗夠寬（電腦）時左選單／中列表／右明細三欄顯示；
  視窗窄（手機）時换成一般的手機排版，同一份程式碼、同一份邏輯。

## 開發環境

這個開發環境（雲端容器）沒有 Android SDK，也不是 Windows，所以沒辦法在這裡
直接編出 `.apk` 或 `.exe`。改用 **GitHub Actions** 在每次 push 之後，用真正
的 Windows 和 Android 環境編譯：

1. 到 repo 的 **Actions** 分頁，找到「編譯 Windows / Android」這個 workflow
   最新一次執行。
2. 執行完成後，下面的 **Artifacts** 會有 `stock_acc-windows`（解壓縮後執行
   `stock_acc.exe`）和 `stock_acc-android`（`app-release.apk`，直接傳到手機
   安裝，需要先允許「安裝不明來源的 App」）。

本機這裡能做、也已經做過的檢查：
```bash
cd app
flutter analyze   # 靜態檢查，沒有錯誤或警告
flutter test      # 手續費、統計、新聞合併邏輯的單元測試，全數通過
flutter build linux --debug   # 驗證程式碼能真的編譯、啟動，不會一開就當掉
```

### Android 更新保留資料（設定一次就好）

Windows 版更新只要把 `.exe` 換掉，資料在另一個地方，不會受影響。Android 不一樣：
沒設定簽章金鑰的話，GitHub 每次編譯都會用一把**新產生**的金鑰簽名，Android 會
認為是不同的 App，安裝新版前要先移除舊版，資料就會被清掉。

設定一次固定金鑰，之後每次更新才能直接蓋掉舊版、保留資料：

1. 到 repo 的 **Actions** 分頁，找到「**產生 Android 簽章金鑰**」這個
   workflow，右上角 **Run workflow** 手動觸發一次。金鑰是在 GitHub 的伺服器上
   產生的，不會經過任何人的電腦。
2. 跑完之後，下面 Artifacts 有一個檔案，下載解壓縮，裡面 `設定步驟.txt` 有
   完整的操作說明；簡單說就是把裡面 4 行資料，分別新增成 repo 的 4 個
   Secrets（**Settings → Secrets and variables → Actions → New repository
   secret**）：`ANDROID_KEYSTORE_BASE64`、`ANDROID_KEYSTORE_PASSWORD`、
   `ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD`。
3. 設定完之後，把「產生 Android 簽章金鑰」那次執行紀錄刪掉（右上角 ··· →
   Delete workflow run），電腦上下載的壓縮檔也刪掉。
4. 重新觸發一次「編譯 Windows / Android」，之後編出來的 apk 才會用這把固定的
   金鑰簽名。**這一版之前裝的 apk 因為金鑰不同，換這一版是最後一次要先移除
   舊版重裝**；之後每次更新都能直接蓋掉安裝，資料保留。

還沒設定這 4 個 Secrets 之前，App 一樣能正常編譯、正常使用，只是每次更新都要
先移除舊版。

## 架構

```
app/lib/
  models/       資料模型（人、帳戶、交易、關注清單）
  logic/        純計算邏輯：手續費／交易稅、移動平均成本法統計（有單元測試）
  data/         本機存檔（JSON 檔）、資料中樞 AppRepository、內建股票代號表
  services/     抓即時股價（證交所）、抓新聞（Google News）
  ui/           畫面：主題、共用元件、導覽殼、各分頁畫面
```

資料存檔是一個 JSON 檔，放在系統的「應用程式資料」資料夾。「匯出備份」就是
把這個 JSON 另存一份，「匯入備份」就是整包讀回來取代——這也是格式已經預留
給第二階段雲端同步的地方：每筆資料都有 `id` 和 `updatedAt`，之後接上雲端時
可以直接拿來判斷哪筆比較新，不用重新設計資料結構。

## 之後的規劃

- **第二階段**：登入 + 雲端同步，手機和電腦資料互通。
- **第三階段**：資訊頁擴充指標圖形、法人買賣、股利等。
- 個股分析（指標、回測、停損停利提醒）規劃成另一個獨立模組，之後另外討論。
